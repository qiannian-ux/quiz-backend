# 贴图号接入方案 · 探我趣测

> 2026-09-27。**目标只有一个**：让"测评结果"这件事，以最低摩擦变成一张能发出去的图，
> 并被发进微信公域流量池（贴图号 / 朋友圈 / 小红书）。
> 贴图号是**渠道**，不是功能——所有接入都要服从"能不能更省地长出内容"这一条。

## L1 · 内容接入（今天就能做，纯前端）

结果页加一个「保存为贴图素材」，一次生成 **3 张 1080×1440** 竖图：

| 图 | 内容 | 用哪个字段 |
|---|---|---|
| 图 1 封面大字 | 结果码超大字 + 展示名 + 一行钩子 | `code` / `name`·`subtitle` / `basic.one_liner` 截一句 |
| 图 2 三个特征 | 三个特征 + 两条优势 | `basic.traits` 前 3 / `basic.strengths` 前 2 |
| 图 3 引导 | 一句建议 + 品牌角标 + 小程序码 | `basic.tip` / 硬编码「探我趣测」/ 小程序码接口 |

**为什么要 3 张而不是 1 张**：贴图号单条 3-6 张一组，封面只是钩子，
后两张才负责"让人看完、愿意点小程序"。一张图能过首屏，但撑不住转化。

### 技术要点（踩坑清单）

1. **canvas 是真组件**，不是方法。uni-app 里必须写 `<canvas type="2d" id="poster">`，
   然后 `uni.createSelectorQuery().in(this).select('#poster')` 取节点、等 `canvas.width` 设好再画。
   想用隐藏 DOM 截图这条路是走不通的。
2. **输出分辨率**：CSS 里给 canvas 一个 1080×1440 的绘制尺寸，
   真机上按 `devicePixelRatio` 换算，避免缩略图发出来是糊的。
3. **小程序码要缓存**：走后端 `getUnlimitedQRCode`（B 接口），`scene` 上限 32 字符。
   每次点都重新生成会被限频 —— 生成一次转 base64，塞进本地缓存复用。
4. **抖音端没有小程序码**，那张图的码位直接空着，别留白边，改放品牌名。
   抖音端也没必要为贴图号接入做适配（贴图号是微信侧的）。
5. **拒绝授权相册不要弹错误**。改成"长按图片保存"的提示，否则一次授权失败就把人赶走了。
6. **品牌角标必须画进图里**（右下角一行小字，柔和点，别像广告）。
   这是整个方案里最值钱的一行代码 —— 用户每发一张，就是一张免费裂变海报。

### 合规

- 保存图片是用户**主动行为**，合规。
- **绝不能做"分享后解锁/加天数"这类引导分享**，那是诱导分享，会限制能力。
- 图里不要留个人微信、手机号、二维码（小程序码可以，那是官方挂载能力的载体）。

## L2 · 文案接入（零开发，体验提升最大）

结果页再加一个「复制文案」，预填好一段可直接粘贴到贴图号的文字：

```
我是 ${name}（${code}），${basic.one_liner}。
你是哪一型？点下面的链接测一测，30 秒出结果。
#MBTI #性格测试 #自我认知
```

**这条的性价比高得离谱**：把"发一条贴图"的时间从 5 分钟压到 30 秒。
贴图号玩法手册里的"每天发 1 条"，真正的壁垒从来不是图，是**愿不愿意花 5 分钟配文案**。

## L3 · 回流接入（要动后端，但只动三刀）

贴图号挂小程序之后，来的都是**冷启动新用户**。要接的其实只有三件事：

### ① 落地页带参数直达（最划算的一刀）
贴图发布时挂小程序链接是可以带 query 的。在 `App.vue` 的 `onLaunch(options)` 里读
`options.query.code`（或 `options.scene`），把它透传给首页 / 结果页 ——
**用户点进来就是他自己那一型的结果页**，而不是一个干巴巴的首页。
这个体验差别，直接决定点击率和留存。

### ② 来源埋点（只为算 ROI）
前端 `uni.setStorageSync('source', 'tietu')`，在 `utils/request.js` 里统一往请求头塞一个
`x-source`。后端不用改表、不用写新接口，日志里能看到就行。
有了它你才知道"贴图号到底给我带来了多少DAU"。

### ③ 新用户首次引导
`user_quiz_record` 为空 = 新用户，走一次"选一套你最想测的"引导页，
而不是直接丢给首页卡片列表。

⚠️ L3 建议**跑满 7 天内容再上**。先验证"贴图号有没有量"，再决定要不要投第二刀。

## 附录 A · 后端 `GET /api/poster/qrcode` 参考实现

> 后端 Java 由你自己敲，这里只给设计（前端已按这个契约写好了）。

**要做什么**：微信「小程序码 B 接口」`wxacode.getUnlimited`，返回图片 buffer。

- 请求：`GET /api/poster/qrcode?scene=<结果码>`
- scene 上限 32 字符，放 `report.code`（如 `INTJ`）刚好
- 返回：`{ "qrPath": "/tmp/qr_INTJ.png" }`——**别返回 base64 塞进 JSON**，
  2048 长度上限会直接截断。落盘成临时文件，返回本地路径。
- 必须缓存：这个接口有限频（.day 5000 次），前端只存一次长期复用即可
- access_token 走项目里现成的获取逻辑，不要每次请求都刷新

前端拿到后调一次 `posterRef.value.cacheQrCode(path)` 写进 storage，之后就一直读缓存。

## 附录：抖音侧能不能接？（2026-09-27 查证）

抖音确实有类似形态 —— 发布作品（图文/视频）时可挂小程序锚点，形态是**视频**不是图文，
而且审核会复查"小程序内是否包含违规能力"。但**门槛完全不是一个量级**：

| | 微信 · 贴图号 | 抖音 · 短视频挂载（UGC） |
|---|---|---|
| 形态 | 3:4 图文，发布时直接挂小程序 | 视频作品带锚点 |
| 主体 | **个人可开**，实名即可 | **个人不支持**，需企业性质 |
| 量级 | 零粉可起量 | **近一月活跃用户 ≥ 10 万** |
| 评级 | — | 评级 A 级 + 主体信用分 ≥ 90 |
| 类目 | — | 须在能力开放类目内 |
| 其他 | 无次数限制 | 申请审核 2-3 个工作日 |

**结论：抖音侧的挂载现在够不着，不必为此调整任何架构。** 抖音端等 DAU 起来、必要时升级主体再申请。

### 抖音端现在就能做的三件事

1. **配分享模板**（不是改代码就有）：抖音开放平台 → 小程序 → 运营 → 流量配置 → 分享设置，
   填分享标题 / 文案 / **图案**，提交审核通过后拿模板 ID 填进 `onShareAppMessage`。
   `result.vue` 现在只有 title 没有 image，分享出去是一张默认卡，**这是最便宜的形象提升**。
2. **「图文转视频」不是小程序能力**，是剪映 / 巨量引擎的创作侧工具。
   正确姿势是运营动作：结果海报 → 剪映图文成片 → 发抖音。**零门槛，现在就能用。**
3. 把抖音端当成一个"内容出口"而不是"转化入口"：先出内容拿曝光，挂载能力未来再补。

### 申请挂载前必须自查的红线

抖音挂载能力审核会复查小程序内是否存在以下能力，命中会**取消通用挂载权限、强制下线 7 天**：

- **诱导分享**（含"分享赚佣金 / 分享得服务"类页面或弹窗）
- **收集线索**（引导用户填写手机等信息）
- **引导致电**（客服、销售电话）
- **引导下载**（下载按钮、文字链、二维码）
- **抽奖活动**（转盘、九宫格等）

⚠️ **我们 `result.vue` 有「翻牌抽卡」（`flipped`）**。它本身不是抽奖（无奖品、无输赢），
但**绝不能做成"分享后开卡"** —— 那会同时踩到抽奖和诱导分享两条。这条上线前值得再确认一次。

## 一个判断

这套接入里，**唯一不可替代的是"结果图本身好不好看"**。
字段、接口、带参、埋点都是配套，不做也能跑，做了只是更顺。
如果时间只够做一件事，就做 L1 —— 而且先做**一张封面图**，
别一上来就铺三张，用最小闭环先跑通"用户愿意存图 → 愿意发"。
