# 学习笔记：微信小程序登录（M4）从零落地

> 日期：2026-09-09
> 项目：探我趣测（uni-app 双端 + Spring Boot 4.1.1）
> 阶段：M4 双端登录与统一用户 · 微信端（抖音端待补）

---

## 一、为什么要做登录

探我趣测 要走**微信虚拟支付**卖探币，而虚拟支付的签名算法里有一项：

```
signature = HMAC-SHA256(sessionKey, signData)
```

`sessionKey` 只能从**登录流程**里拿到（微信 `code2Session` 返回）。所以：

> **没有登录 = 没有 session_key = 虚拟支付签名算不出来 = 收不了钱。**

登录在这个项目里不是"锦上添花的用户体系"，而是**支付的硬前置**。

---

## 二、完整登录链路

```
① 小程序端 uni.login()                → 拿到一次性 code（5分钟有效）
② POST /api/auth/login {code,platform} → 把 code 发给自家后端
③ 后端 code + appid + AppSecret        → 调微信 jscode2session
④ 微信返回 openid + session_key
⑤ 查 user_platform(platform, openid)
   ├─ 查不到 → 新建 user + 新建 user_platform（同一事务）
   └─ 查到   → 更新 session_key（每次登录都会变，必须刷新）
⑥ 签发 JWT
⑦ 返回 { token, userId, coinBalance }
```

**为什么第③步必须后端做**：因为要用 `AppSecret`（小程序的密码），它绝不能出现在前端代码里——小程序包可被反编译。

## 三、数据库设计：为什么要两张表

```sql
user            (id, coin_balance, created_at)              -- 业务身份
user_platform   (id, user_id, platform, openid, session_key, updated_at)  -- 平台身份
```

**关键认知：微信和抖音的 openid 不互通，且没有共同的 unionid。**

所以"统一用户"的现实做法是**分层**：

- 主表 `user` 装业务数据（探币、答题记录）——**跟着"人"走**
- 身份表 `user_platform` 装各平台凭证——一个人可挂微信 + 抖音两条

这样将来即使用手机号打通了两端，业务数据也不用迁移。

其他设计点：
- `UNIQUE(platform, openid)` —— 数据库层面兜底，防止同一用户被重复建多条身份
- `coin_balance` 放主表不放身份表 —— 探币属于"人"，不属于"某个平台的账号"

## 四、落地的文件清单

| 层 | 文件 | 职责 |
|---|---|---|
| 数据 | `domain/User.java` | 主账号实体 |
| 数据 | `domain/UserPlatform.java` | 平台身份实体 |
| 数据 | `mapper/UserMapper.java` | 继承 `BaseMapper<User>` |
| 数据 | `mapper/UserPlatformMapper.java` | 继承 `BaseMapper<UserPlatform>` |
| 传输 | `dto/LoginRequest.java` | 接 `{code, platform}` |
| 传输 | `dto/LoginResponse.java` | 返 `{token, userId, coinBalance}` |
| 工具 | `util/JwtUtil.java` | 签发 / 校验 JWT |
| 服务 | `service/WxAuthService.java` | 调微信 code2Session |
| 服务 | `service/AuthService.java` | 核心登录逻辑（`@Transactional`） |
| 接口 | `controller/AuthController.java` | `POST /api/auth/login` |

**DTO 为什么不能省**：实体是数据库表的镜子，字段一一对应。`UserPlatform` 里有 `sessionKey`——如果接口直接返回实体，session_key 就泄露了。**DTO 是白名单**，物理上保证敏感字段出不去。

## 五、关键知识点

### 1. code 是一次性门票
`uni.login()` 拿到的 code **5 分钟有效、只能用一次**。前端拿不到 openid（防伪造身份），只能拿这张票让**后端**去换。

### 2. session_key 的两个用途
- 解密用户敏感数据（如加密的手机号）
- **虚拟支付签名**（本项目特有）

它**绝不能返回前端**，且每次 `wx.login()` 都会刷新——**所以每次登录都必须 update**，不更新就是旧值，支付时签名校验必失败（`-15005`）。

### 3. JWT 是 base64，不是加密
```
header.payload.signature
```
前两段谁都能解出来看。所以里面**只放** `userId` + `platform` + 过期时间，**绝不放** session_key / openid / 手机号。
第三段签名只保证"内容没被篡改"，不保证"看不见"。

### 4. `api.weixin.qq.com` 不用加小程序域名白名单
白名单管的是**小程序前端**发出的请求；code2Session 是**后端服务器**发出的，不受限制。

### 5. LambdaQueryWrapper 的方法引用
```java
new LambdaQueryWrapper<UserPlatform>()
    .eq(UserPlatform::getPlatform, platform)
```
`UserPlatform::getPlatform` 不是调用方法，是告诉 MyBatis-Plus "我要用 platform 这个字段"。它反推出列名。**好处：字段名写错编译期就报错**，不像手写字符串 `"platform"` 那样运行时才炸。

## 六、踩坑记录（最值钱的部分）

### 坑 1：`characterEncoding=utf8mb4` 驱动不认
- **现象**：`java.sql.SQLException: Unsupported character encoding 'utf8mb4'`
- **原因**：`characterEncoding` 要的是 **Java 字符集名**（`UTF-8`），`utf8mb4` 是 MySQL 内部字符集名，两者不是一回事
- **解法**：直接删掉这个参数（MySQL Connector/J 8.0+ 默认就是 utf8mb4），或写成 `UTF-8`

### 坑 2：改了 `spring.sql.init.mode=never`，启动时 DataLoader 崩
- **现象**：`Failed to obtain JDBC Connection`，堆栈指向 `DataLoader.run()` → `QuestionMapper.selectCount`
- **原因**：项目有个 `CommandLineRunner` 在启动时查题库；`never` 关掉了 `schema.sql` 自动建表，MySQL 里根本没有 `question` 表
- **解法**：改回 `always`（`schema.sql` 用的是 `create table if not exists`，幂等安全）
- **教训**：改配置前先想清楚"谁依赖它"

### 坑 3：`@Value` 导成了 Lombok 的
- **现象**：`@Value` 用在构造器参数上报错
- **原因**：IDE 自动导入选了 `lombok.Value`（类级注解，生成不可变类），而非 Spring 的 `org.springframework.beans.factory.annotation.Value`
- **教训**：**注解用不了，第一件事看 import**。`@Value`、`@Data`、`@Builder` 这些短名字最容易撞车

### 坑 4：字段少个字母 d，引发两个错
- **现象**：`Cannot resolve method 'setUpdatedAt'`
- **原因**：实体写的是 `private LocalDateTime updateAt`，Lombok 生成 `setUpdateAt()`
- **更隐蔽的第二层**：`updateAt` 会被映射成列名 `update_at`，而表里叫 `updated_at` —— 就算编译过了，插入时报 `Unknown column`
- **教训**：**字段名必须和数据库列名严格对应**（驼峰 ↔ 下划线），一个字母都不能差

### 坑 5：Mapper 泛型填成了另一个 Mapper
- **现象**：`LambdaQueryWrapper<UserPlatform> 无法转换为 Wrapper<UserMapper>`
- **原因**：`UserPlatformMapper extends BaseMapper<UserMapper>`，尖括号里填错
- **为什么藏得深**：两个 Mapper **同包**，引用 `UserMapper` 不需要 import，编译器认为语法合法
- **教训**：新建 Mapper 后第一件事——检查 `BaseMapper<>` 尖括号里的类型

### 坑 6：MySQL 版本要跟服务器对齐
- 本地装 5.7 还是 8.0？**必须 8.0**（服务器是 8.0）
- 差异会咬人：8.0 新增保留字（`rank`/`row_number`/`groups`/`system`，用作字段名要加反引号）、默认排序规则 `utf8mb4_0900_ai_ci`、认证插件 `caching_sha2_password`
- **"本地能跑、上线就挂"的根源，九成是环境不一致**

### 坑 7（提前避开的）：小皮面板安装路径
MySQL 启动失败第一大原因——**安装路径含中文或空格**。装到 `D:\phpstudy_pro` 这种纯英文无空格路径。

## 七、安全要点（M6 的雏形）

| 项 | 做法 |
|---|---|
| AppSecret / AppKey / JWT 密钥 | 不进前端、**不进 Git**，走 IDEA 环境变量或配置中心 |
| session_key | 只存库，**绝不返回前端**、不写进 JWT |
| JWT 载荷 | 只放 userId / platform / exp |
| userId 来源 | **从 JWT 解析**，绝不信前端传参（防越权） |
| ThreadLocal | 请求结束**必须 remove()**，否则线程池复用导致用户串号 |
| 401 响应 | 只说"未登录/登录已失效"，不暴露是签名错还是过期 |
| 放行清单 | 只放行 `/api/auth/login`、`/api/quiz/random`，克制 |
| 数据库连接 | 3306 不对公网开放；应用用专用账号（`guiz`）而非 root |
| 日志 | 不打密钥、session_key、token、完整请求 URL |

**最反直觉的一条**：`ThreadLocal.remove()`。Tomcat 线程池复用线程，不清 ThreadLocal 的话，下一个请求可能读到上一个用户的 userId——**A 看到 B 的探币**。只在并发时偶发，极难排查。

## 附：这次能写进简历的点

不要只写"实现了微信登录"，要写**决策和踩坑**：

- 主账号与平台身份**分层建模**，支撑微信/抖音双端 openid 不互通的现实
- 识别到 `session_key` 是虚拟支付的签名依赖，在登录流程中**强制刷新并落库**
- 用 DTO 白名单**从结构上杜绝**敏感字段（session_key）外泄
- 本地环境与生产 **MySQL 版本对齐**，规避保留字与排序规则差异

> 讲"为什么这么做"比讲"用了什么库"有说服力得多。
