# 双后端架构约定（阿里云 Spring Boot + 微信云开发）

> 背景：阿里云轻量服务器（`wangwang2.asia`）是**唯一的核心后端**，服务微信 / 抖音 / 未来的网页三端。
> 微信云开发是白嫖来的半年资源，定位是**微信端专属的可摘除增强层**，到期不付费就功能降级，主流程不受影响。

## 一、红线（最重要，先记住这一条）

**云开发不存任何"丢了会心疼"的数据。**

它只做无状态的加工型能力：内容安全、订阅消息、海报生成、云存储做临时中转。
所有需要长期留存的数据（用户、答题记录、结果、图片归档）一律落到 Spring Boot + MySQL。

理由：半年后云环境释放，云存储里的 fileID 会全部失效。如果业务数据里存了 fileID，
用户历史分享图、历史结果全部变死链，而迁移成本远高于一开始就不存。

## 二、职责划分

| 能力 | 放哪 | 摘除后的降级方案 |
| --- | --- | --- |
| 登录（code → openid → JWT） | Spring Boot | 不涉及 |
| 题库、答题记录 | Spring Boot | 不涉及 |
| 算分、结果 | Spring Boot | 不涉及 |
| 结果图**归档** | Spring Boot（自己的磁盘/OSS） | 不涉及 |
| 结果图**生成** | 云开发云函数 | 前端 canvas 本地生成 + 保存相册 |
| 内容安全（文本/图片检测） | 云开发（微信官方接口免鉴权） | 后端接腾讯云/其他审核，或先关闭 |
| 订阅消息 | 云开发 | 不做（抖音端本来也没有） |
| 云存储 | 仅作**临时中转**，生成后立刻回传 Spring Boot | 前端直传 Spring Boot |

注意最后一行：海报在云函数里生成 → 存云存储拿 fileID → **立刻把二进制回传 Spring Boot 归档** → 前端只保存 Spring Boot 返回的归档 URL。这样云环境没了，老图片照样能打开。

## 三、解耦的三条硬规则

**规则 1：能力开关，不要写死分支。**
不要在业务代码里散落 `if (用云开发) ... else ...`。统一在 `utils/cloud.js` 里做平台适配层：

- 微信端：真实实现 + `isCloudEnabled()` 开关
- 非微信端（抖音/H5）：导出**同名空实现**，返回 `null` / `true` / `false`

这样页面代码完全不需要条件编译，直接 `import { generatePoster } from '@/utils/cloud.js'`，
拿到 `null` 就走本地降级。半年后关开关，业务代码一行不改。

**规则 2：`wx.cloud.init` 必须 try/catch，且不能阻塞进页面。**
云环境欠费/释放后 init 会失败。如果写在 `App.vue` 的 `onLaunch` 里还 `await`，
主流程会跟着卡死。正确做法：init 失败只置 `cloudReady = false`，页面照常渲染。

**规则 3：开关从后端下发，不要硬编码在前端。**
前端写死 `true` 的话，到期那天必须发新版才能关，而小程序审核要 1-3 天。
让 Spring Boot 提供一个 `GET /api/config` 返回 `{ wxCloud: true }`，
前端启动时拉一次存本地，云能力挂了在后台改一个值就全网生效。

## 三之二、依赖方向：互相交流只许单向

两个后端在半年共存期内**需要互相交流**，但方向必须严格单向：

**允许（云开发 → Spring Boot）**
云函数通过 HTTPS 调 `wangwang2.asia` 的接口：查题库、存结果、拉用户资料。
理由：云函数是无状态加工层，需要主干的数据时自己来取。

**禁止（Spring Boot → 云开发）**
主干**绝不**反向调云函数、绝不读云数据库、绝不假设云存储里有数据。
理由：一旦主干反向依赖，半年后摘掉云开发时主干会跟着断 —— 这直接违背"基础服务不受损"的底线。

一句话记：**云开发是主干的调用方，主干永远不是云开发的调用方。**

### 互相交流具体长什么样（云函数 → 主干的调用样例）

"互相交流"在单向约束下，就是**云函数需要时自己来主干取 / 写**，主干从不回头找云函数。
一个微信端云函数的典型样子（Node.js + `wx-server-sdk`，注意里面没有任何 uni-app API）：

```js
// cloudfunctions/quizProxy/index.js
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const BASE = 'https://wangwang2.asia'

exports.main = async (event) => {
  // 1) 微信身份只在云函数里拿，不传给主干当"凭据"
  const { OPENID } = cloud.getWXContext()

  // 2) 调主干的公开 / 服务接口（数据宿主在主干）
  const q = await (await fetch(`${BASE}/api/quiz/random`)).json()

  // 3) 如需写回（答题、结果），用"服务令牌"调主干，不是用户 JWT
  await fetch(`${BASE}/api/quiz/submit`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-Service-Token': process.env.SVC_TOKEN   // 主干信任的固定服务密钥
    },
    body: JSON.stringify({ openid: OPENID, payload: event })
  })

  // 4) 返回加工结果，自己不留数据
  return q
}
```

要点：
- **身份不跨层**：`OPENID` 是微信给云函数的，主干只认自己的 `JWT` / 服务令牌，云函数用 `X-Service-Token` 这种 server-to-server 密钥调主干，不把微信身份当主干凭据。
- **公开接口 vs 服务令牌**：纯读（如 `/api/quiz/random`）可直接走公开端点；要写（答题/结果）走带 `X-Service-Token` 的服务端点，主干单独校验，和用户登录的 JWT 体系解耦。
- **永远不留数据**：云函数处理完就 return，任何需要留存的东西都写回 `wangwang2.asia`，云存储只做临时中转（见第二节）。

## 三之三、移除保证（基础服务无感知）

摘掉云开发后基础服务必须照常运行，靠三条保证：

1. **主干零反向依赖**：上一条守住，主干代码里搜不到任何云函数 / 云数据库的调用。
2. **数据宿主在主干**：结果、图片归档全在 Spring Boot + MySQL / 自有 OSS，云存储只做临时中转且立刻回传。
3. **前端开关降级**：`utils/cloud.js` 的 `isCloudEnabled()` 返回 false 时，页面走本地 canvas / 关闭订阅消息，能力"无感消失"。

三条都满足，摘云开发就是后台改一个值 + 删云函数，主干零改动、零数据迁移。

## 四、到期摘除清单（半年后照着做）

1. 后台把 `/api/config` 的 `wxCloud` 改成 `false`
2. 确认：`结果图归档` 一直走的是 Spring Boot（是的话什么都不用迁）
3. 云开发控制台删除云函数、清空云存储
4. 前端 `utils/cloud.js` 里的微信分支可以留着（有空实现兜底，不会报错），也可以整个删掉

只要第 2 步成立，其余都是 5 分钟的事。

## 五、uni-app 接入云开发的三个必需配置

uni-app 编译到微信小程序后，产物就是标准的小程序代码，`wx.cloud` 是微信原生 API，
**技术上云开发的全部能力（云函数 / 数据库 / 云存储 / 内容安全）都能正常调用**。
但 uni-app 的构建流程不认识云函数目录，必须手动配三件事：

**1. manifest.json 声明云函数目录**

```json
"mp-weixin": {
  "appid": "",
  "cloudfunctionRoot": "cloudfunctions/"
}
```

HBuilderX 里切到「源码视图」加这一行。

**2. 把 cloudfunctions 目录复制到构建产物（Vue3 项目必须）**

uni-app 不会自动拷贝云函数，不配的话微信开发者工具里根本看不到这个目录。
项目根目录新建 `vite.config.js`：

```js
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'
import fs from 'fs-extra'
import path from 'path'

const plugins = [uni()]

if (process.env.UNI_PLATFORM === 'mp-weixin') {
  plugins.push({
    name: 'copy-cloudfunctions',
    buildStart() {
      fs.copySync(
        path.join(process.env.UNI_INPUT_DIR, 'cloudfunctions'),
        path.join(process.env.UNI_OUTPUT_DIR, 'cloudfunctions')
      )
    }
  })
}

export default defineConfig({ plugins })
```

需要 `npm i -D fs-extra`。**坑：cloudfunctions 目录不能为空**，先放个占位文件，否则复制会静默失败。

**3. 云函数要单独部署，HBuilderX 管不了**

云函数改动后，必须在**微信开发者工具**里右键云函数目录 →「上传并部署：云端安装依赖」。
uni-app 的热更新只覆盖前端代码，云函数不在它的管辖范围。这意味着调试链路是：
改云函数 → 微信开发者工具上传 → 前端重新调用，比纯前端开发长一截。

> 云函数里是纯 Node.js 环境 + `wx-server-sdk`，**不能写 uni-app 的 API**，也拿不到 `@/` 别名。

## 六、几个提醒

- **个人主体可以开通云开发**，不用担心资质问题。基础免费档：数据库 2GB、读 5 万/天、写 3 万/天、存储 5GB、云函数并发 20。
- **白嫖的是「AI 应用及线上工具小程序成长计划」**（2026 全年激励期）：新开发者免费创建个人版云开发环境，**有效期 6 个月**；顺带还送 1 亿 Token 混元文生文额度 + 1 万张文生图额度 + We 分析专业版 1 年。要求小程序类目落在文娱/工具/社交/深度合成/资讯虚拟这几类 —— 测评属「工具」，符合。6 个月这个有效期正好印证了"可摘除"设计不是过度设计。
- **2026 年起小程序必须 ICP 备案**，未备案会被下架。域名 `wangwang2.asia` 备案了不等于小程序备案了，这是两回事，要在微信公众平台单独走小程序备案流程（个人备案约 7-20 个工作日）。这个周期要提前算进去。

- **云开发环境和小程序 AppID 强绑定**，抖音端完全没有对应能力。所以这块天然就是 `#ifdef MP-WEIXIN`，和已有约定一致，不额外增加复杂度。
- 云函数如果需要访问 MySQL，别直连（服务器要放行 IP，不安全）。让云函数通过 HTTPS 调 `wangwang2.asia` 的接口即可，域名已备案。
- 白嫖有代价：云开发会让架构多一层。简历上可以讲"核心域与平台增强能力分离、可降级架构"，这是加分项；但如果讲不清楚，反而是减分项。想清楚再写进去。
- 抖音端没有云开发，也就没有内容安全。等接入用户生成内容（昵称、自定义测评结果）时，**抖音端的审核要后端统一做**，别指望平台能力对齐。
