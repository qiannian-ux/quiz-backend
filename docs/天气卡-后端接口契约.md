# 天气卡 · 后端接口契约

小程序首页顶部「今天天气」卡片的数据来源。前端已完成，后端缺这一个接口。

---

## 1. 接口定义

```
GET /api/weather?city=成都
```

| 项 | 说明 |
|---|---|
| 参数 `city` | 城市中文名，必填（前端已保证非空） |
| 鉴权 | 无需登录，未接入 JWT（将来要加也行） |
| 超时 | 前端 `TIMEOUT = 10000`，建议后端上游超时 3s、读取超时 5s |

**成功响应（200）**

```json
{
  "ok": true,
  "city": "成都",
  "code": 100,
  "text": "晴",
  "temp": 26,
  "emoji": "☀️"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | boolean | 必须是 `true`；省略或 `false` 前端一律走降级展示 |
| `city` | String | 展示用的城市名。经过地理编码规范化更好（如"成都"）；直接回传参数也行 |
| `code` | int | 和风天气状态码，前端暂不使用，留着给后续分Weather类型用 |
| `text` | String | 天气描述，"晴/多云/小雨/雪…"，前端靠它挑配色和一句话提示 |
| `temp` | Number | 当前温度，单位摄氏度，**允许小数**，前端自己四舍五入 |
| `emoji` | String | **可选**。后端给最好，省得前端维护一份天气码到 emoji 的映射表 |

**失败**：直接抛异常返回 4xx/5xx，或返回 `{ "ok": false }`。
前端不做任何 toast 打扰，卡片降级成「获取失败 / 点一下重试」。

## 2. 实现方案（和风天气）

### 2.1 注册与配额
1. 注册 https://console.qweather.com/ ，免费开发版
2. 新建应用 → 选 **Web API**（不要选小程序 SDK，那个是另一个 key）
3. 拿到的 `key` 就是下面要用的

免费版：最多 2 个 key，**每天 1000 次**请求。只在天气卡加载/手动刷新时调用，完全够用，**不需要做限流**，但建议缓存。

### 2.2 两步：城市名 → 城市 ID → 实况

**第一步：地理编码**（把"成都"换成 location id）

```
GET https://geoapi.qweather.com/v2/city?location=成都&key=<KEY>
```

响应：
```json
{ "code": "200", "location": [
    { "id": "1012701", "name": "成都", "timeZone": "Asia/Shanghai", ... }
]}
```
取 `location[0].id`；数组为空 = 城市不存在，返回 400。

**第二步：实时天气**

```
GET https://devapi.qweather.com/v7/weather/now?location=1012701&key=<KEY>
```

响应：
```json
{ "code": "200", "now": {
    "obsTime": "2026-09-20T14:00+08:00",
    "temp": "26", "text": "晴", "code": "100",
    "windDir": "西南风", "relativeHumidity": "52", ...
}}
```
字段都在 `now` 里，注意 `temp`/`code`/`text` 是 String，要转。

`code` → `text` 的官方对照表：
```
100 晴 | 101 多云 | 102 少云 | 103 晴间多云 | 104 阴
200-202 短暂阵雨  203-204 雷阵雨  205-208 阵雪
300-305 小雨  306-309 中雨  310-312 大雨
400-402 小雪  403-404 中雪  405-406 大雪
500-502 雾  503-504 冻雾  507-508 霾
```
完整对照表见 https://dev.qweather.com/docs/api/weather/ 。建议直接把 100~508 映射写进一个 `Map<Integer, String>` 常量，查不到就返回"未知"。

### 2.3 缓存

同一城市 10 分钟以内直接返回上次结果，别每次打上游。简易实现：

```java
private final Map<String, WeatherDTO> cache = new ConcurrentHashMap<>();
private final Map<String, Long> at = new ConcurrentHashMap<>();
```

天气变化慢，10 分钟足够；也可以按天算（同一天同一城市只查一次）。

## 4. 骨架代码（可直接抄）

无第三方依赖，用 JDK 自带 `HttpClient`：

```java
@RestController
@RequestMapping("/api/weather")
public class WeatherController {

    @Value("${weather.key:}")
    private String key;

    @GetMapping
    public Map<String, Object> now(@RequestParam String city) throws Exception {
        // 1. 缓存命中直接返回
        // 2. 无 key -> 直接 throw，前端走降级
        // 3. geoapi 换 id -> devapi 取实况 -> 组装 DTO
    }
}
```

异常统一交给全局 `GlobalExceptionHandler` 返回 500，别手写 try/catch 吞异常。

## 5. 部署检查

1. 微信后台 → 开发管理 → 服务器域名：**`request` 合法域名保持只有 `wangwang2.asia` 即可**，不需要加和风域名（是后端在打，与小程序无关）
2. 阿里云安全组 / 服务器出网：和风是 HTTPS 443，默认放行
3. 接口不通时前端表现：卡片显示「📍 获取失败 / 点一下重试」，**不会弹错误 toast**，属于预期行为，方便你判断"到底是我后端挂了还是前端挂了"

## 本地跑起来测

```powershell
$env:JAVA_HOME='D:\job\JDK'
.\mvnw.cmd spring-boot:run
```

服务起在 8080（dev 配置没写 server.port，走默认）。另开一个 Terminal：

```powershell
curl.exe -G "http://localhost:8080/api/weather" --data-urlencode "city=成都"
```

| 结果 | 说明 |
|---|---|
| `{"ok":false,...,"msg":"天气服务未配置"}` | ✅ 链路通，只是 key 还没填（**不是 401** 就说明白名单生效了） |
| `401` | ❌ 白名单漏了，检查 WebMvcConfig |
| `500` | ❌ 代码异常，看 spring-boot:run 窗口的堆栈 |
| 连接被拒绝 | ❌ 服务没起来，或端口不是 8080 |

填了 key 之后重跑，应看到 `{"ok":true,"city":"成都","code":100,"text":"晴","temp":26,"emoji":"☀️"}`。
同一个城市连打两次，第二次不会再打上游（缓存生效）。
