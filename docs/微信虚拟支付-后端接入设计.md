# 微信虚拟支付（个人主体 · 道具直购）后端接入设计

> 适用：探我趣测小程序（个人主体，类目「工具」，已认证备案）
> 目标：用「打赏 / 请作者喝奶茶」「¥5.9 解锁全站测评」两个道具，跑通微信虚拟支付全流程
> 分工：**前端（uni-app）已由我接好**；**后端（Spring Boot 接口）由你实现**，本文件是完整设计与代码骨架

---

## 0. 产品道具清单（需在 MP 后台【虚拟支付 → 道具管理】新建并发布）

| productId     | 名称            | 价格（分） | 发货动作（权益）                     |
| ------------- | --------------- | ---------- | ------------------------------------ |
| `unlock_all`  | 解锁全站测评    | 590        | 标记该用户 `premium=true`            |
| `tip_milktea` | 请作者喝奶茶    | 600        | 仅记录打赏订单，**不发放任何权益**   |

> 打赏多档位 = 多个道具（如 `tip_milktea_2` = ¥12.00）。本 demo 先用一档。
> 道具价格（goodsPrice）必须以「分」为单位、且与后台配置严格一致，否则签名/对账失败。

## 1. 前置条件（来自官方文档，先逐项确认）

- 个人主体 + 中国大陆居民身份证 + 服务类目含「工具」+ 已完成认证、备案
- 全终端**月支付限额 10 万元**
- 费率：Android 等 **1%**；iOS **12%**（含 Apple 佣金）
- 开通后拿到三要素：**AppID / OfferID / 现网 AppKey**（虚拟支付 → 基本配置）
- iOS 支付额外：需配置**小程序简称** + 开 Apple IAP
- **只做道具直购（short_series_goods），不引入代币 / 余额体系**

## 2. 两套签名（精确算法，官方 5.5 节）

### 2.1 paySig（服务端用 AppKey 算）
```
msg    = "requestVirtualPayment" + "&" + signData        // signData 是 JSON 字符串
paySig = HMAC-SHA256(AppKey, msg)  → 十六进制小写
```

### 2.2 signature（服务端用 sessionKey 算，用户态签名）
```
signature = HMAC-SHA256(sessionKey, signData)  → 十六进制小写
```
> 注意：signature 的 msg **不带** `requestVirtualPayment&` 前缀，只有 signData 本身。

### 2.3 查单签名 pay_sig（B 端，转发 /xpay/query_order 用）
```
msg      = "/xpay/query_order" + "&" + bodyJson
pay_sig  = HMAC-SHA256(AppKey, msg)  → 十六进制小写
```

### 2.4 ⚠️ 致命坑：signData 的 JSON 键顺序必须固定
官方明确要求：`post_body` 必须与实际请求体**完全一致（不格式化、不改键顺序）**。
**禁止用 Gson/Jackson 默认序列化**（会按字母序重排键，导致签名对不上）。
固定键顺序（务必照抄）：
```json
{"offerId":"...","buyQuantity":1,"env":0,"currencyType":"CNY","productId":"...","goodsPrice":590,"outTradeNo":"...","attach":"..."}
```

Java 里**手动拼 JSON 字符串**（或 LinkedHashMap + 有序 ObjectMapper），不要依赖字段名排序。

## 3. 服务端接口清单

| 接口              | 调用方         | 作用                                       |
| ----------------- | -------------- | ------------------------------------------ |
| `POST /api/pay/order`  | 前端           | 生成 outTradeNo + signData + paySig/signature，返回 payData |
| `POST /pay/notify`     | 微信发货推送   | 验签 + 幂等 + 发货，返回 XML `<ErrCode>0</ErrCode>` |
| `POST /api/pay/query`  | 前端 / 定时任务 | 转发 `/xpay/query_order`，兜底查单补发货    |

> URL 前缀说明：`/api/pay/order`、`/api/pay/query` 走你现有 JWT 拦截器（需登录）；
> `/pay/notify` 是微信回调，**不能**走 JWT，需在拦截器白名单放行（见 §6）。

## 4. POST /api/pay/order（前端调）

请求体：
```json
{ "productId": "unlock_all", "attach": "可选透传，发货时原样返回" }
```
（`attach` 建议填 userId 或 openid，便于发货时定位用户）

处理流程：
1. 从 JWT 取 `userId` → 查 `user_platform` 拿到 `openid` 与 `session_key`。
2. 校验 `productId` 合法，查道具配置拿 `goodsPrice`（分）。
3. 生成 `outTradeNo`：`"T" + 毫秒时间戳(13位) + 4位随机` → 8–32 位、**不能下划线开头**、全局唯一、**不可复用**。
4. 用固定键顺序拼 `signData`（§2.4）。
5. `paySig = calcPaySig(signData, appKey)`；`signature = calcSignature(signData, sessionKey)`。
6. 落库订单（状态 `PENDING`，见 §7）。
7. 返回给前端：
```json
{
  "offerId": "你的OfferID",
  "signData": "{\"offerId\":\"...\",...}",
  "paySig": "十六进制",
  "signature": "十六进制",
  "env": 0,
  "outTradeNo": "T...",
  "mode": "short_series_goods"
}
```
> `mode` 前端 `utils/payment.js` 已固定补 `short_series_goods`，后端返回不返回都行；这里返回一份更稳妥。
> 前端 `buyProduct()` 直接把该对象透传给 `wx.requestVirtualPayment`，前端**不重算任何签名**。

## 5. POST /pay/notify（微信发货推送，XML / JSON 双格式）

- 配置入口：MP 后台【开发管理 → 消息推送】填服务器地址 = `https://wangwang2.asia/pay/notify`（小程序虚拟支付的发货推送即走此地址，无独立入口）。
- 事件固定 `Event = xpay_goods_deliver_notify`。
- **数据格式取决于 MP 后台【消息推送】配置的「数据格式」（XML 或 JSON），加密方式可选明文 / 兼容 / 安全。代码已做成双格式兼容，四种组合均支持**：
  - 加密包：XML 外层为 `<xml><Encrypt>…</Encrypt></xml>`；JSON 外层为 `{"Encrypt":"…"}` → 取密文 → 验 `msg_signature` → AES-256-CBC 解密（密钥 = Base64Decode(EncodingAESKey + "=")，IV = 密钥前 16 字节，明文结构 random(16B)+len(4B)+msg+appid）。
  - 明文 / 兼容模式：直接解析，无需解密。
- 关键字段（嵌套也能取到）：
  - `OpenId`：发给谁
  - `OutTradeNo`：下单时的业务单号（**发货主键**）
  - `WeChatPayInfo.MchOrderNo`：**平台单号 `wx_order_id`**（幂等去重首选，允许为 null）
  - `GoodsInfo.ProductId` / `GoodsInfo.Quantity`：道具与数量

处理流程（对应 `PayService.handleNotify`）：
1. 按外层格式提取密文（或直接取明文）；安全模式下先验 `msg_signature` = SHA1(字典序 token+timestamp+nonce+encrypt)。
2. AES 解密后，内层按首字符判 XML / JSON 并解析；JSON 走 `flattenJson` 把 `WeChatPayInfo` 等嵌套对象的叶子字段提到顶层。
3. 非 `xpay_goods_deliver_notify` 事件 → 直接回成功 ack，避免微信无限重试。
4. **幂等双保险**：① 按 `wx_order_id` 查到已发货 → 成功；② 按 `outTradeNo` 查到 `status=1` → 成功（微信最多重试 15 次）。
5. **发货**：更新 `pay_order.status=1` 并回写 `wx_order_id`。
   - 说明：`unlock_all` 的解锁态由前端支付成功时写 `storage.premium`，后端**不写 `user` 表**；`tip_milktea` 仅记打赏不发放权益。服务端权益以 `pay_order.status=1` 为唯一可信来源。
6. **回包格式必须跟随请求格式**（否则微信可能不认，触发重试）：
```xml
<!-- 请求为 XML 时 -->
<xml><ErrCode>0</ErrCode><ErrMsg><![CDATA[success]]></ErrMsg></xml>
```
```json
// 请求为 JSON 时
{"ErrCode":0,"ErrMsg":"success"}
```
> 官方也接受**空响应**或字面量 `success`（等价于 ErrCode=0）。

## 6. POST /api/pay/query（兜底查单）

- 转发微信 `POST /xpay/query_order`，需带 `pay_sig`（B 端 uri=`/xpay/query_order`）。
- 请求体：
```json
{ "openid": "用户openid", "env": 0, "order_id": "业务单号 outTradeNo" }
```
- `pay_sig = calcQuerySig(bodyJson, appKey)`（见 §2.3）。
- 用途：发货推送丢失时主动查单。建议**定时每 5 分钟**扫 `PENDING` 订单查单补发。
- 查到「已支付」但本地未发货 → 复用 notify 的发货逻辑（同一幂等键 `wx_order_id`）。

> **⚠️ 发货推送验签说明（标记不确定点）**：官方 5.4.1 只写「服务器校验签名」，未给推送体签名算法。
> 接入时以微信官方/MP 后台实际推送字段为准。稳妥做法：
> ① 若推送 XML 自带 `signature` 字段 → 按官方最新字段用 AppKey 验（同 §2 模式，uri=notify 路径）；
> ② 同时依赖【消息推送】配置的 **Token** 做来源校验（GET 验证 + POST 消息体 SHA1 验签）；
> ③ 至少保证 HTTPS + 幂等 + 仅接受微信来源（可选 IP 白名单）。
> 不要因为验签细节卡住整体——**幂等 + HTTPS + 来源校验**已能挡住绝大多数伪造。

现有 `user_quiz_record` 是测评记录，不适合放支付单。建议新增：

## 8. session_key 来源与刷新

- `wx.login` → `auth.code2Session` 拿 `session_key`，存在 `user_platform.session_key`（明文，AES 延后）。
- **支付前必须是最新 session_key**（旧值会报 `-15005` 签名错）。
- `session_key` 不返前端、不进 JWT、不进 Git。

## 9. 退款 / 结算（需告知用户）

- Android 等：开发者可主动退款（MP 后台或 `refund_order` 接口）。
- iOS：用户向 App Store 申请，**开发者不能主动退款**。
- 手续费：支付 180 天内退款平台退还手续费；超期不退。
- 结算：Android **T+3**；iOS **约 45–60 天**。

## 10. 红线（官方七、Agent 注意事项）

- 只做道具直购，不引代币。
- `outTradeNo` 每次下单重新生成、全局唯一（8–32 位、不下划线开头），不复用。
- 签名 `post_body` 必须与实际请求体完全一致、不变键序；`appKey` 用正式 AppKey。
- **发货以 `wx_order_id` 幂等为准**；前端 `success` 回调可能丢失，**绝不作为发货依据**。
- 金额单位永远是「分」，全程不换算；`env` 固定 `0`。

## 11. 注意事项（消息推送与成本）

- **启用消息推送配置本身不花钱。** MP 后台【开发管理 → 消息推送】只是填一个回调 URL + Token，**免费**。产生费用的是「用微信云托管 / 云函数去接收」那部分（容器要 7×24 常驻算力，最小规格约 ¥21/月起）。
- **⚠️ 纠正（重要）：小程序虚拟支付的发货推送就是走【消息推送】这个地址，没有独立的"发货推送 URL"入口。** 小程序个人虚拟支付的 `xpay_goods_deliver_notify` 推送，微信会投递到【开发管理 → 消息推送】填的那个服务器地址（即本项目的 `/pay/notify`）。所以**这个页必须配、不能跳过**。早期文档写成"通用消息推送用不到、虚拟支付有独立发货推送 URL"是照小游戏/旧文档写的，**对小程序不适用，以本段为准**。
- **配置页填法（URL/Token/EncodingAESKey/加密方式/数据格式，见截图）**：
  - URL = `https://wangwang2.asia/pay/notify`
  - Token / EncodingAESKey = 自定义并**保存好**（后端生产配置要填一样的）
  - 加密方式 = 安全模式（推荐）；数据格式 = XML
  - 点"保存"时微信发 **GET** 握手（带 `signature/timestamp/nonce/echostr`），后端验签后原样回 `echostr`；正式推送是 **POST**（安全模式下 body 是 `<Encrypt>` 密文，后端先 AES 解密）。
- **后端已配套实现 GET 握手 + 安全模式 AES 解密**（见 PayController `/pay/notify` 的 GET/POST 两个方法 + PayService 的 `verifyEcho`/`handleNotify`/`decryptMsg`/`sha1`）。生产配置需补 `wx.vpay.push-token`、`wx.vpay.aes-key` 两个值（与 MP 后台填的 Token / EncodingAESKey 一致）。
- **不要把发货推送接到云托管。** 你有现成的阿里云 Spring Boot，直接填自有 `/pay/notify` 即可，**零额外成本**。
- 云托管宣传的「免鉴权」只是帮你自动验签的便利，不是必需；本项目已用 Token 验签（GET）+ msg_signature 验签（POST 安全模式）+ AES 解密自行实现。

## 附录 A：Java 签名代码（可直接用）

```java
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.HexFormat;

public class VPaySign {
    public static String hmacSha256(String key, String msg) throws Exception {
        Mac mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(key.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
        byte[] raw = mac.doFinal(msg.getBytes(StandardCharsets.UTF_8));
        return HexFormat.of().formatHex(raw); // 十六进制小写
    }

    // 支付签名 paySig（C 端 uri 固定 requestVirtualPayment）
    public static String calcPaySig(String signData, String appKey) throws Exception {
        return hmacSha256(appKey, "requestVirtualPayment&" + signData);
    }

    // 用户态签名 signature（无 uri 前缀）
    public static String calcSignature(String signData, String sessionKey) throws Exception {
        return hmacSha256(sessionKey, signData);
    }

    // 查单签名 pay_sig（B 端 uri = /xpay/query_order）
    public static String calcQuerySig(String bodyJson, String appKey) throws Exception {
        return hmacSha256(appKey, "/xpay/query_order&" + bodyJson);
    }
}
```
