Interface Design Proposal · v2

探我趣测 · 界面设计方案

一套面向微信 / 抖音双端小程序的设计系统：把"每张卡一个渐变"收敛成"中性底座 + 单一强调色"，用间距与字阶建立层级，用状态与反馈建立信任。

v2.0 设计系统 微信 / 抖音 双端 uni-app Vue3 750rpx 基准
01

设计目标

这一版要解决的核心矛盾：测评类小程序的浏览成本低、决策快，用户平均停留时间短；而当前界面用色过散，用户"看得见热闹，看不见重点"。

扫得懂

3 秒内知道这一页能干什么、下一步点哪里。信息层级由间距和字重承担，而不是靠颜色。

点得准

所有可点区域不小于 88rpx（约 44px），禁用态有明确视觉差异，不出现"点了没反应"的元素。

信得过

加载 / 空 / 出错三态齐全，隐私承诺可见可查，让"结果不出手机"这件事被感知到。

02

四条设计原则

原则不是口号，每一条都对应一次具体的取舍判断。

① 克制用色，让颜色承担意义

颜色只出现在两类地方：行动点（主按钮用品牌紫）和结果本身（人格类型专属色）。其余一律走中性色，否则颜色就从"信号"退化为"噪音"。

② 用留白和字阶建立层级

标题与正文拉开至少 8rpx 字差，区块之间用 24–32rpx 间距分隔。层级靠"疏密"而非"边框"，卡片不再密贴。

③ 每个元素都有状态

可点元素必须有默认 / 按下 / 禁用三态；异步操作必须有加载反馈；列表必须有空态。没有状态的界面会让人怀疑"是不是点错了"。

④ 关键动线一步直达

"想测一次"这条主干路：首页 → 选测评 → 答题 → 结果，全程不超过 4 次点击。收藏、分享等次级动作靠后，不抢主按钮。

与 v1 的关键差异。上一版把每张测评卡做成不同渐变，视觉上热闹但失去了"重点"。
v2 把渐变收回到结果卡这唯一的高光时刻，其余区域降为背景——对比一下就是你中有我时的"彩虹"vs"留白 + 一点紫"。

06

页面规范

五个页面的信息层级与交互要点。核心动线是"首页 → 答题 → 结果"，其余页面都是它的延伸。

首页→ 选测评→ 答题→ 结果→ 收进卡册

首页 · 决策台

区域内容交互要点
问候区按时段变化的问候语 + 上次测得什么右侧「已测 N」徽标，纯展示不可点
今日卡 hero唯一允许铺渐变的区域已抽 / 未抽两种真实状态，非永远一个样
测评列表白底的卡片网格，每张一个彩色图标底显示题数与预计时长，降低决策成本

关键取舍：测评卡不再整张铺色。改为白底 + 一块彩色图标底（家族色），既保留了辨识度，又让整页有了主次。

答题页 · 单任务聚焦

区域内容交互要点
进度条顶部通栏，当前 / 总数宽度平滑过渡，给人"快做完了"的推进感
题干卡30rpx 大字，行高 1.5一次只显示一题，避免滚动和误触
量表5 档圆点 + 左右锚点文案选中态放大并填充主色；未选时下一题禁用
底部操作固定吸底，避开 iPhone 安全区禁用态明确定灰 + 点击给出原因提示

结果页 · 情绪高点

区域内容交互要点
类型 Hero该类型专属渐变 + 大号类型码 + 名称全页唯一高饱和区域，停留型内容
维度条四组对比，胜出端高亮入场时 0 → 目标宽度动画，延迟 120ms
解读卡描述 / 优势关键词 / 职业方向关键词用胶囊标签，便于速读
操作区主：收入卡册；次：再测 / 分享主次分明，主按钮唯一

诚实性约束：深度解读若尚未解锁，卡片直接隐藏而非显示灰色占位——不展示用户拿不到的东西。

记录页 / 我的 · 数据归位

区域要点
记录页相对时间实时计算（刚刚 / 3 小时前 / 2 天前）；左侧类型色块便于肉眼分类
我的 · 资料头像、昵称可编辑并持久化；统计三项全部由记录算出，无写死数字
我的 · 卡册16 格全铺开，未解锁显示锁；点开看详情
我的 · 菜单每一项都必须有真实响应；分享项须用原生 button 触发
07

动效与反馈

动效的作用是"解释发生了什么"，不是装饰。统一时长与曲线后，整个 app 的手感会变得一致。

场景时长曲线效果
页面转场240msease-out位移 + 淡入
卡片入场320mscubic-bezier(.2,.8,.2,1)上移 16rpx，逐项延迟 40ms
按钮按下120msease-out缩放到 0.97
底部弹层280mscubic-bezier(.2,.9,.25,1)底部滑入 + 遮罩淡入
维度条900mscubic-bezier(.2,1,.36,1)宽度生长
必须提供降级。开启系统「减弱动态效果」时，所有位移 / 缩放动效时长归零，仅保留透明度过渡——前庭敏感用户会因过度动画感到不适。
08

易用性与平台适配

这一节决定"能不能顺利过审"以及"长辈能不能用"，不是可选项。

触控与可读

  • 所有可点区域 ≥ 88rpx（约 44px）
  • 正文不小于 24rpx，辅助文字不小于 22rpx
  • 相邻可点元素间距 ≥ 16rpx，避免误触
  • 输入框聚焦时自动上推，不被键盘遮挡

状态完备

  • 异步 → 骨架屏或 loading，禁止白屏等待
  • 空数据 → 空态 + 明确出口按钮
  • 请求失败 → 错误态 + 可点击重试
  • 破坏性操作（清空）→ 二次确认弹窗

双端平台规范

  • 导航栏留出系统状态栏高度，不做自定义假导航
  • 底部预留 Home 指示条安全区
  • 抖音端无支付能力，相关入口用条件编译整体剔除
  • 分享必须用平台原生 button，view 点击无法唤起

隐私可感知

  • 「结果仅在本地计算」在结果页可见
  • 隐私说明可随时从「我的」进入
  • 提供一键清空本地数据
  • 不索取手机号等无关权限（也避免审核被拒）
09

落地路线

建议按"令牌 → 组件 → 页面"三层推进，每完成一层都能独立验证，避免一次性大改导致无法定位问题。

第 1 步

替换设计令牌

App.vue 全局 CSS 变量换成新色板 / 字阶 / 圆角 / 阴影三级。此步不改任何结构。

第 2 步

沉淀通用组件类

补齐 .u-btn / .u-chip / .u-sheet / .u-empty，并把 .u-card 换成"描边 + 分级投影"。

第 3 步

逐页迁移

顺序：结果页（收益最大）→ 首页 → 我的 → 记录 → 答题。每页迁移完在真机跑一遍。

过渡期建议。表情符号目前承担了图标职责，短期可继续用，但要统一放进圆角色底（28–32rpx），并保证同一类图标大小一致。中期建议换成线性图标集，这是拉开观感差距最明显的一步。
