## 第 3.5 步：环境变量（WX_APPID / WX_SECRET / JWT_SECRET）怎么设

应用通过 `${WX_APPID:}` / `${WX_SECRET:}` / `${JWT_SECRET:}` 读取这三个值。  
Spring Boot 解析优先级：**命令行 `-D` > 系统环境变量 > 配置文件**。填法任选其一（两处都填同值会互相覆盖，别混）：

**A. 最简单：直接写进服务器外部 `application-prod.properties`**（推荐，前提是该文件在 jar 同目录且不进 Git）

```
# 把下面三行的 ${WX_APPID:} 等占位符整行替换成真实值，改完环境变量就完全不需要设
wx.appid=wx你的真实appid
wx.secret=微信公众平台显示的secret
jwt.secret=一段够长的随机串
```

即：删掉 `${WX_APPID:}` 这种写法，直接写 `wx.appid=真实值`。**服务器文件写明文即可**；**仓库/IDE 里的 `src/main/resources/application-prod.properties` 保持 `${...}` 占位符、不要写真值**（jar 打包后也是占位符，万一误提交也不泄密）。两者用同一个文件名，靠"jar 外 > jar 内"的优先级让服务器明文覆盖仓库占位符。

**B. 想用真正的环境变量（让 properties 只留占位符、密钥不落盘）：启动前 export**

```bash
# 临时（仅当前终端有效，但 nohup 子进程会继承）
export WX_APPID="wx..."
export WX_SECRET="..."
export JWT_SECRET="..."

# 更稳妥：写进启动脚本 start.sh，每次都用它起，重启也不丢
cat > /www/wwwroot/quiz-backend/start.sh <<'EOF'
#!/bin/bash
export WX_APPID="wx..."
export WX_SECRET="..."
export JWT_SECRET="..."
cd /www/wwwroot/quiz-backend
nohup java -jar quiz-backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod > quiz.log 2>&1 &
EOF
chmod +x start.sh
./start.sh
```

> 坑：`export` 只在当前 shell 会话有效。直接 export 后 `nohup ... &` 能继承；但服务器重启或别人手动起 jar 时若没先 export，变量就丢了。**长期运行务必走 start.sh 或下面的 Supervisor。**

**C. 用 Supervisor 托管（第 5 步进阶推荐）——在 program 配置里加一行：**

```
environment=WX_APPID="wx...",WX_SECRET="...",JWT_SECRET="..."
```

**D. 用宝塔「Java 项目」托管——面板里有「环境变量」输入框，逐条填 `WX_APPID=...` 即可。**

**验证是否生效：** 启动后 `grep -i "wx.appid\|jwt" quiz.log` 看不到明文（密钥不打日志，正常）；要确认变量进了应用，可调一次登录接口看能否拿到 openid——若 `WX_APPID`/`WX_SECRET` 为空或填错，`code2Session` 会返 `40013 invalid appid`，据此反推。

## 配置安全：生产密钥放服务器到底安不安全

**结论：明文配置放在你自己控制的服务器上是 Spring Boot 部署的常态做法，对个人作品集项目"足够安全"，但要做 3 件廉价加固。不用上 Vault/KMS（过度设计，违背 M6「别为作品集过度安全投入」）。**

真正的风险按大小排：

1. **误提交进 Git（最高危）** —— 已用 `.gitignore` 排除 `application-prod.properties` / `.env` / `secrets/` / `docs/backup-*.sql`，且本仓库当前还没 `git init`。保持：① 仓库里的 `src/main/resources/application-prod.properties` 只写占位符 `${WX_APPID:}`（别写真值）；② 永远别 `git add -f` 它；③ 一旦 commit，密钥就永久在 Git 历史里，删文件也救不回。
2. **被公网直接下载（最该修，可修）** —— 若 `/www/wwwroot/quiz-backend/` 是宝塔站点根目录、Nginx 又默认静态托管，那 `https://wangwang2.asia/application-prod.properties` 可能被直接下载。两个改法任选：
   - 把配置文件移出 Web 根：`/etc/quiz-backend/application-prod.properties`，启动加 `--spring.config.additional-location=/etc/quiz-backend/`；或
   - 在宝塔站点「配置文件」(Nginx) 加拒绝规则：`location ~* \.(properties|yml|yaml|env)$ { return 403; }`。
3. **文件权限** —— `chmod 600 application-prod.properties`，属主设为跑 jar 的用户，别让其他用户可读。

为什么这个文件法比「环境变量 `-D`」更安全：`-Dwx.secret=xxx` 会显示在 `ps aux` 里，服务器上任何本地用户都能看到；而文件法至少不进进程列表。（环境变量用 Supervisor/start.sh 的 `environment=` 也不进 ps，但本质同样"密钥落盘"，只是换了地方。）

密钥泄露的"爆炸半径"已被你的架构天然缩小：

- **DB 密码**：3306 不对公网（只 127.0.0.1），所以即使库密码泄露，攻击者也只能从服务器本机连，外网用不了。
- **JWT_SECRET**：设长随机串；真泄露就换一个（代价是所有旧 token 失效，可接受）。
- **WX_SECRET**：在微信公众平台后台一键重置即可。

兜底：服务器整体被 root  compromise 时，本地任何存法都救不了——那是 SSH/防火墙层面的事（只用密钥登录、安全组只开 80/443/22）。宝塔备份/服务器镜像若包含 `/www/wwwroot` 也会带走该文件，注意备份访问权限。

## 第 3.6 步：虚拟支付配置（打赏 / 解锁功能需要）

后端 4 个支付类（PayController / PayService / PayOrder / PayOrderMapper）已打进 jar，但以下值**必须配在外部 `application-prod.properties`（jar 同目录）**才生效，否则默认空、启动不报错：

- `wx.vpay.offer-id`   = 微信后台【虚拟支付 → 基本配置】的 OfferID
- `wx.vpay.app-key`    = 同上 AppKey（现网）
- `wx.vpay.push-token` = 【开发管理 → 消息推送】填的 Token（GET 握手验签用，必须与 MP 后台填的**一字不差**）
- `wx.vpay.aes-key`    = 【消息推送】的 EncodingAESKey（43 位，安全模式 POST 解密用）

> ⚠️ key 名带 `wx.vpay.` 前缀：`push-token` 不是 `token`、`aes-key` 不是 `key`。名字错/漏配 → 启动不报错，但 `/pay/notify` 握手/解密失败。
> ⚠️ **外部配置必须被 jar 加载到**：若启动 jar 时当前目录不是 `/www/wwwroot/quiz-backend`，Spring 只加载 jar 内部的占位符（`${...}`），外部真实值读不到 → 这 4 个值全空。启动务必 `cd /www/wwwroot/quiz-backend` 再起，或加 `--spring.config.additional-location=/www/wwwroot/quiz-backend/`。

## 附录：标准打包 + 服务器重启流程（复制即用）

每次改完后端代码要部署，固定走下面这套。本地 Windows（PowerShell）+ 服务器 Linux（bash）各一段，按顺序复制执行。

### A. 本地打包（Windows PowerShell）

```powershell
# 1. 指定好的 JDK（别用损坏的 corretto-17，那个 JDK 会报 Failed setting boot class path）
$env:JAVA_HOME = "D:\Users\35156\.jdks\ms-17.0.20.1"

# 2. 用项目自带 mvnw 重新打包（本机没装 Maven，首次联网下载 Maven 引导包）
.\mvnw.cmd clean package -DskipTests

# 3. 产物：target/quiz-backend-0.0.1-SNAPSHOT.jar（约 33MB，含当天编译的 class）
```


## 安全红线（M6）

- 服务器安全组只放行 **80 / 443 / 22**；**3306 不对公网开放**。
- WX_SECRET / JWT_SECRET / DB 密码不进前端代码、不进 Git（走配置文件或环境变量）。
- session_key 不返前端、不进 JWT、不打日志。
