# 动态测评（后端可配置增删）· 重构思路与代码骨架

> 配套：`docs/前端重构-需求与设计.md`（R1 配置驱动多测评 / R4 后端驱动功能开关）
> 分工：后端 .java 由你自写，本文给**思路与代码骨架**（非可直接运行，按你实际包名/字段名微调）；前端你也说"我亲自写代码"，故同样给骨架。
> 目标：**加 / 删一套测评 = 操作数据库（或配置），不改代码、不发版**；前端首页完全数据驱动。

---

## 0. 一句话原则

> 测评是**数据**，不是**代码**。`quiz` 表的一行 = 一套测评；首页只负责"把后端给的列表画出来"。

---

## 1. 现状对照：为什么现在做不到"动态"

| 现状 | 问题 |
|------|------|
| 前端 `api/quiz.js` 写死 `QUIZ_CODE='mbti'` | 加第二套测评要改常量 |
| 原型首页卡片是硬编码 `quizzes` 数组 | 列表不来自后端，加测评前端无感知 |
| 后端 `quiz` 表已有 `code/name/status` | **数据模型基本具备**，但缺展示字段 |
| 后端只有 `GET /api/quiz/{code}`（出题），**没有列表接口** | 前端无从拿到"有哪些测评" |
| `quiz` 表缺 `emoji` / `tag` / `sort_order` | 首页卡（图标/分类/顺序）没地方存 |

**结论**：数据层 90% 已就绪，缺三样——
1. `quiz` 表补 3 个展示字段（`emoji` / `tag` / `sort_order`）
2. 后端一个**列表接口** `GET /api/quiz/list`
3. 前端首页**改为数据驱动**（删硬编码数组）

## 2. 数据库变更（一步，幂等 ALTER）

MySQL 8 **不支持 `ADD COLUMN IF NOT EXISTS`**（之前踩过坑），用 `information_schema` 判断的幂等写法：

```sql
-- 给 quiz 补首页卡片需要的展示字段；可重复执行
DROP PROCEDURE IF EXISTS `add_quiz_cols`;
DELIMITER $$
CREATE PROCEDURE `add_quiz_cols`()
BEGIN
  IF NOT EXISTS (SELECT 1 FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='guiz' AND TABLE_NAME='quiz' AND COLUMN_NAME='emoji') THEN
    ALTER TABLE `quiz` ADD COLUMN `emoji` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '卡片图标 emoji';
  END IF;
  IF NOT EXISTS (SELECT 1 FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='guiz' AND TABLE_NAME='quiz' AND COLUMN_NAME='tag') THEN
    ALTER TABLE `quiz` ADD COLUMN `tag` VARCHAR(16) NOT NULL DEFAULT '' COMMENT '分类标签：性格/职业/情感/能力';
  END IF;
  IF NOT EXISTS (SELECT 1 FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='guiz' AND TABLE_NAME='quiz' AND COLUMN_NAME='sort_order') THEN
    ALTER TABLE `quiz` ADD COLUMN `sort_order` INT NOT NULL DEFAULT 0 COMMENT '首页展示顺序，越小越靠前';
  END IF;
END$$
DELIMITER ;
CALL `add_quiz_cols`();
DROP PROCEDURE IF EXISTS `add_quiz_cols`;
```

**增 / 删一套测评的操作语义**（无需改代码）：
- **增**：`INSERT` 一行 `quiz`（含 `emoji/tag/sort_order/status=1`），并配套插 `dimension` / `question` / `question_option` / `quiz_result` 全套内容层。下次首页加载即出现。
- **删**：`UPDATE quiz SET status=0 WHERE code='xxx'`（**软删**）。已测用户的 `user_quiz_record` 仍保留，只是首页不再展示。

## 4. 前端步骤（逐步，给骨架）

### Step F1 · `api/quiz.js` 加列表方法，去掉"写死 code"
```js
// 新增：拉测评列表（首页用）

  return get('/api/quiz/list')   // 返回 QuizListItem[]
}
// 保留：QUIZ_CODE 仅作"本地兜底默认"，不再用于列表
export const DEFAULT_QUIZ = 'mbti'
```

### Step F2 · 首页改为数据驱动（删硬编码数组）
```js
// pages/home/home.vue 的 onMounted
import { getQuizList } from '@/api/quiz.js'
import { LOCAL_QUESTIONS } from '@/data/questions.js'  // 仅兜底

const quizzes = ref([])
onMounted(async () => {

    quizzes.value = await getQuizList()

### Step F4 · 卡片点击带 code 进答题页

- 卡牌翻牌、收入卡册逻辑直接复用 prototype 里的 `drawCard / flip / collectCard`。

## 5. 运行时流程走查（过一遍）

```
A. App 启动
   └─ App.vue: silentLogin() 失败也不阻塞（红线①）
      （可选）syncFeatures() 拉功能开关

B. 首页 onMounted
   └─ GET /api/quiz/list  ──成功──▶ 按 sort_order 渲染卡片网格
        │失败（后端挂/超时）
        └─ 兜底：只画 MBTI 本地卡（红线②：仍有得玩）

C. 点卡片
   └─ navigateTo /pages/quiz/quiz?code=xxx
      └─ onLoad → useQuiz(code).loadQuestions()
          └─ GET /api/quiz/{code}  ──成功──▶ 后端题
               │失败
               └─ 本地题库兜底（questions.js）

D. 答题
   └─ 每题 next() 存 answers
   └─ 末题 → submitQuiz(code) 交后端算分（红线③：防篡改）
        │失败
        └─ 本地 calcResult(answers, code) 兜底

E. 翻牌抽卡（prototype 的 drawCard/flip）
   └─ 露出角色卡 → 收入卡册
      └─ 写 user_quiz_record（后端）/ 本地 album

F. 后台配置变更（动态核心）
   ├─ INSERT 新 quiz 行           → 下次首页加载自动出现，零代码改动
   └─ UPDATE quiz SET status=0    → 首页消失，历史记录保留

G. 红线回顾
   ├─ 登录失败 → 游客照测
   ├─ 后端挂   → 本地兜底 MBTI
   └─ 密钥/签名 → 只在后端，前端不碰
```

## 6. 增删测评的两种配置方式

| 方式 | 做法 | 何时做 |
|------|------|--------|
| **A（推荐，现在就能用）** | 直接 SQL 操作 `quiz` 表（INSERT / `UPDATE status=0`） | 本阶段；你已在用 SQL 灌库 |
| B（后续） | 管理接口 + 轻量后台页面，免 SQL | 等测评多到不想手敲 SQL 时 |

> 注意：方式 A 下"删"请用软删（`status=0`），别 `DELETE`——`user_quiz_record` 通过 `quiz_id` 关联，硬删会让历史记录变孤儿。
